### Semantic Summary

#### Key Functionality
This class, `MagicMatch`, is part of the Apache Tika project and is used to define and evaluate magic matches for file types. A magic match is a way to identify file types based on specific byte sequences that are unique to certain file formats.

#### Core Logic
The core logic of this class revolves around creating and using a `MagicDetector` to check if a given byte array matches the specified magic pattern. The `eval` method checks if the provided data matches the defined magic pattern, while the `size` method returns the length of the expected match.

#### Inputs/Outputs
- **Inputs:**
  - `byte[] data`: The input byte array to be checked against the magic pattern.
  - `MediaType mediaType`: The media type associated with the magic pattern.
  - `String type`: The type of the magic pattern (e.g., "magic", "signature").
  - `String offset`: The offset within the file where the magic pattern starts.
  - `String value`: The actual byte sequence that constitutes the magic pattern.
  - `String mask`: A mask that specifies which bytes in the `value` should be considered during the comparison.

- **Outputs:**
  - `boolean`: The result of the evaluation (`true` if the data matches the magic pattern, `false` otherwise).
  - `int`: The length of the expected match.

#### Dependencies
- **Apache Tika Project**: This class is part of the Apache Tika library, which is used for detecting and extracting metadata from various file types.
- **MagicDetector Class**: The `MagicMatch` class depends on the `MagicDetector` class, which is responsible for parsing and evaluating the magic patterns. The `MagicDetector` is created and managed by the `MagicMatch` class.

In summary, the `MagicMatch` class provides a mechanism to define and evaluate magic patterns for identifying file types, leveraging the `MagicDetector` to perform the actual matching.
